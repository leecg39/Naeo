# NAEO 네이버 블로그 발행 도우미

NAEO에 저장한 초안을 MCP로 읽어 제목·본문·사진·소제목 단위로 옮기는 Manifest V3 확장입니다. 확장은 클립보드 복사와 편집 위치 선택까지만 수행합니다. 붙여넣기, 소제목 메뉴 선택, 카테고리·공개 설정, 발행 버튼은 회원이 직접 조작합니다.

## 로컬 설치

1. Chrome/Ego Lite의 확장 프로그램 관리 화면에서 **개발자 모드**를 켭니다.
2. **압축해제된 확장 프로그램을 로드합니다**를 누르고 이 `extension` 폴더를 선택합니다.
3. 프로젝트 루트의 `.env.local`에 `NAEO_EXTENSION_IDS=lacdnccodopejadkbeannbcmbljiodik`를 넣고 서버를 다시 시작합니다. `.env.example`은 설정 예시이므로 Next.js가 읽지 않습니다.
4. 확장 아이콘을 눌러 사이드 패널을 열고 서비스 주소를 입력한 뒤 **NAEO로 로그인**을 누릅니다.
5. NAEO 로그인·동의 후 저장한 글을 선택합니다. 네이버 글쓰기 탭을 활성화하고 각 행을 눌러 안내대로 붙여넣습니다.

Manifest의 공개키가 개발용 ID를 고정하므로 같은 폴더를 다시 로드해도 허용 목록 값이 바뀌지 않습니다. Chrome Web Store에 게시할 때는 스토어가 부여한 실제 ID를 서버 허용 목록에 추가해야 합니다.

## 로그인 창에 “유효하지 않은 요청입니다”가 표시될 때

`/auth/extension`은 `extension_id`가 서버의 `NAEO_EXTENSION_IDS` 허용 목록에 있고 `code_challenge`가 전달돼야 로그인·동의 화면으로 이동합니다. 허용 목록이 비어 있거나 설치된 확장 ID가 빠져 있으면 이 오류가 표시됩니다.

위 로컬 설정을 적용한 뒤 오류 창을 닫고 확장 패널의 **NAEO로 로그인**을 다시 누르세요. 허용 ID가 여러 개라면 쉼표로 구분해 기존 값을 보존합니다. 로그인 이후 MCP 요청도 같은 허용 목록을 확인하므로 이 설정은 인증과 초안 조회 모두에 필요합니다.

## “Only one web auth flow is allowed at a time”가 표시될 때

이전에 연 인증 창이 남아 있는데 새 인증 요청을 시작하면 Chrome이 이 오류를 반환합니다. 로그인은 서비스 워커에서 한 번만 실행하며, 여러 패널의 요청은 같은 결과를 기다립니다. 패널을 닫거나 다시 열어도 인증 완료·토큰 저장은 백그라운드에서 이어지고, 로그인 중에는 주소 입력과 로그인 버튼이 비활성화됩니다.

수정본은 `chrome://extensions`에서 이 확장의 **새로고침**을 누른 뒤 패널을 다시 열어 적용합니다. 확장 새로고침만으로 기존 인증 창이 닫히지는 않습니다. 오류가 표시되면 **이전 로그인 창 닫기**를 누른 뒤 다시 로그인하세요. 이 버튼은 입력한 NAEO 주소와 이 확장 ID가 일치하는 인증 페이지의 단일 탭 팝업만 닫습니다. 일반 브라우저 창과 다른 앱의 인증 창은 유지합니다. 외부 로그인 제공자 화면으로 이동해 식별할 수 없는 창은 직접 닫아야 합니다.

회귀 검증: `node --test tests/extension-auth.test.mjs tests/extension.test.mjs`. 실제 서비스 워커·패널 코드를 실행하면서 브라우저 API를 대체해 동시 요청, 패널 재열기, 취소·재시도, 남아 있는 인증 창, PKCE·콜백 검증을 확인합니다.

## 권한 경계

- `identity`: OAuth PKCE 로그인 창과 `chromiumapp.org` 콜백
- `storage`: 이 브라우저에 OAuth 토큰과 행 진행 상태 저장
- `clipboardWrite`: 회원이 누른 행의 텍스트·서식·사진 복사
- `scripting`, `activeTab`, 네이버 호스트 권한: 네이버 SmartEditor ONE에서 제목·본문·보이지 않는 사진 앵커·소제목 위치 찾기
- 선택적 호스트 권한: 회원이 입력하고 승인한 NAEO 서버 한 곳에 OAuth/MCP 요청

확장은 키 입력, 자동 붙여넣기, 자동 발행, 네이버 계정 비밀번호 접근을 하지 않습니다.
