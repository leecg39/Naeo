# Ego 포인트 빈값·충돌 검증

2026-10-16

운영 데이터와 분리한 SQLite 데이터베이스와 production build를 사용했다. 같은 로그인 세션을 공유하는 Ego 탭 두 개를 390×844로 열어 두 화면 모두 수령 전 상태에서 시작했다.

## 빈값과 잠금 이유

- 잔액 `0P`, `아직 받은 포인트가 없습니다.`, 활성화된 `오늘 출석하고 5P 받기`를 확인했다.
- 블로그 등록, 메이트 진단, AI 인용 현황, 랭킹·서브 주제, 휴대폰 인증의 다섯 단계가 모두 비활성화됐고 각 잠금 이유가 화면에 표시됐다.
- 문서 가로 넘침은 0이었다.

## 수령·충돌·새로고침

첫 탭에서 실제 포인터로 출석 버튼을 눌러 `5P를 받았습니다.`, `오늘 출석 완료`, 원장 `출석 +5P` 한 건과 성공 안내 포커스를 확인했다.

두 번째 탭에는 수령 전 버튼이 그대로 남아 있었다. 이 오래된 버튼을 실제 포인터로 눌렀을 때 서버는 추가 지급하지 않고 `이미 수령한 보상입니다.`를 반환했다. 화면은 `5P`, `오늘 출석 완료`, 원장 한 건으로 수렴했고 성공 안내가 포커스를 받았다. 이어 실제 포인터로 `새로고침`을 눌러도 잔액 5P와 원장 한 건이 유지됐다.

DB에는 해당 회원의 출석 한 건·5P, 포인트 원장 한 건·잔액5만 존재했다. 상세 근거는 [실행 요약](evidence/ego-mobile-admin-2026-10-16/summary.json)에 기록했다.
