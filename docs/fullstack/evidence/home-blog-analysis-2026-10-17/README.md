# 홈 블로그 분석 기능 — 2026-10-17

## 구현

- 홈의 캡처 폼을 `BlogAnalysisForm` React 슬롯으로 교체했다. 주소/ID 검증, Enter 제출, 수집 중 상태, 중복 제출 방지, 결과 대기 취소, 오류·재시도, 결과 재열기를 제공한다.
- 실제 `/api/mate/diagnose` → 네이버 공개 RSS 수집 → 규칙 기반 5개 지표 분석 → 저장 리포트의 흐름을 사용한다. 로그인 없이 분석할 수 있고, 로그인된 요청의 리포트는 내 기록·대시보드에 연결된다.
- 서버와 화면이 같은 주소 파서를 사용한다. 아이디, 일반/모바일 블로그·글 주소, `PostList.naver`/`PostView.naver?blogId=`를 지원한다. 수집 요청은 검증된 ID와 고정 RSS 호스트로만 만든다.
- 마이그레이션 50은 `mate_reports.source_json`에 블로그 제목·URL과 최근 글 최대 30개의 원문·제목·발행일·분류·태그를 보존한다. 공유 링크·내 기록·개인 데이터 내보내기에 같은 근거를 제공한다. 기존 리포트는 근거가 없어도 계속 열린다.
- 공개 글이 없는 유효 RSS는 `422 NO_PUBLIC_POSTS`로 처리하며 점수를 저장하지 않는다. 존재하지 않는 블로그와 네이버 일시 장애는 각각 404·502로 구분한다.
- 홈 설명을 실제 분석 범위에 맞췄다. 결과는 RSS 운영 지표이며 네이버의 공식 점수나 실제 AI 인용률을 뜻하지 않는다.

## 실제 확인

- Ego Lite TaskSpace 22, 로그인된 기존 QA 블로그 계정.
- `https://blog.naver.com/PostView.naver?blogId=leecg39&logNo=224444669929`를 홈에서 Enter로 제출했다.
- 공개 글 1개, 62점. 수집 원문은 `https://blog.naver.com/leecg39/224444669929`이며 제목 51자·태그 9개를 확인했다. 실제 API 응답은 `real-report.json`에 보존했다.
- 빈 입력 시 입력란 포커스와 인라인 오류를 확인했다. 존재하지 않는 블로그는 입력값을 유지하고 재시도 버튼을 표시했다.
- 페이지 네트워크 지연을 2.5초로 설정해 진행 표시, 비활성 제출 버튼, 읽기 전용 입력, Enter 중복 제출 방어, 취소 후 늦은 응답이 결과창을 다시 열지 않는 동작을 확인했다. 확인 후 네트워크 설정을 원복했다.
- 10분 5회 제한에 도달하면 서버의 429 안내가 인라인 표시됐다. 제한을 우회하거나 초기화하지 않았다. 저장된 결과 재열기 → `/dashboard?blog=leecg39` 이동을 확인했다.
- 1428×747 및 390×844에서 결과·폼을 확인했다. 모바일 가로 넘침 없음. 라이트 테마의 입력 글자색/배경색을 확인한 뒤 원래 다크 테마로 돌렸다.

## 범위

- RSS에 공개된 글만 분석한다. 전체 게시물 수·비공개 글·전체 본문 평가를 뜻하지 않는다.
- 점수는 기존 `rules-v1`(발행 빈도·최근성·제목 길이·태그 활용·주제 일관성)을 사용한다. AI 인용 공급자는 미설정이며 인용 실측값을 만들지 않는다.
- 대기 취소는 브라우저의 결과 수신을 중단한다. 이미 서버에서 시작된 분석은 기록에 남을 수 있다는 설명을 화면에 표시한다.
- 기존 무료 진단 제한(IP 10분 5회, 블로그 시간당 10회, 전체 시간당 300회)은 유지한다.
