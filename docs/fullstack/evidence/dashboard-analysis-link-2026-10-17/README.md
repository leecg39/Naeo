# 블로그 분석 결과의 대시보드 표시 수정

대상: `http://127.0.0.1:3000/dashboard?blog=realtek123` · 2026-10-17

## 원인

회원의 `realtek123` 진단 기록은 정상 저장되어 있었고, 대시보드 서버도 해당 블로그의 최신 점수와 글 수를 선택하고 있었다. 하지만 최근 REA 화면에서 진단 컴포넌트를 페이지 하단의 닫힌 `블로그 진단 상세`에 넣어, 첫 화면에는 아직 설정되지 않은 AI 인용과 검색 노출 영역만 보였다. 재현 시 진단 영역은 데스크톱 화면 상단에서 약 1,967px 아래에 있었다. 홈 리포트에 저장된 RSS 수집 근거도 대시보드 데이터에 전달되지 않았다.

## 수정

- 최신 진단 점수, 공개 글 수, 분석 시각, 5개 기준과 리포트 링크를 대시보드 상단에 항상 표시한다. 점수 추이와 과거 기록만 하단 상세에 유지한다.
- 선택한 본인 블로그의 가장 최근 진단에 해당하는 RSS 근거만 전달한다. 새 블로그 스캔 아래에 과거 무료 진단의 근거를 붙이지 않으며, 근거가 없는 과거 리포트의 점수는 그대로 표시한다.
- 홈 리포트와 대시보드가 동일한 공개 글 근거 컴포넌트를 사용한다. 원문 목록은 최대 30개이며, 수집한 전체 공개 글 수와 구분해 안내한다.
- 상단 `변경` 목록에서 등록된 블로그와 무료 분석 기록이 있는 블로그를 모두 선택할 수 있다. 저장된 진단을 선택하거나 조회하는 동작은 블로그를 신규 등록하거나 다시 수집하지 않는다.

## 실제 브라우저 확인

Ego Lite의 동일 로그인 세션에서 확인했다.

1. 저장된 `realtek123` 진단의 62점·공개 글 50개가 대시보드 상단에 표시되고, 닫힌 `details` 조상 요소가 없음을 확인했다.
2. 블로그 변경 목록에서 `leecg39`를 선택하면 해당 블로그의 공개 글 1개와 원문이 표시되고, `realtek123`으로 돌아오면 공개 글 50개와 해당 블로그 원문만 표시되었다.
3. 홈에 `https://blog.naver.com/realtek123`을 입력하고 실제 공개 RSS를 다시 분석했다. 2026-10-17 15:17 KST의 새 결과는 **62점·공개 글 50개·원문 근거 30개**였다.
4. 결과의 `대시보드에서 분석 보기`를 클릭하면 `/dashboard?blog=realtek123`으로 이동했다. 점수·시각·원문 목록이 홈 리포트와 같았고, 새로고침 후에도 유지되었다. [비교 결과](home-dashboard-roundtrip.json)
5. 1428×747 데스크톱과 390×844 모바일에서 점수가 바로 표시됨을 확인했다. 모바일 가로 넘침은 없었고, 원문 근거 목록을 펼쳐 해당 블로그의 링크를 확인했다.

화면: [데스크톱](dashboard-desktop.png), [모바일](dashboard-mobile.png), [모바일 원문 근거](source-mobile.png). 모바일 캡처는 새 분석 전인 15:11 저장 기록이며, 점수·공개 글 수·원문은 새 분석 결과와 동일하다.
