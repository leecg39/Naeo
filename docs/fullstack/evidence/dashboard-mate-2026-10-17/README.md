# 무료 진단 → 대시보드 연결

2026-10-17. 사용자 `/dashboard` 피드백: 진단한 블로그 내용을 대시보드에 시각화.

## 수정 내용

무료 진단은 `mate_reports`에 저장되지만 대시보드는 `scan_results`만 조회하고 있었다. 이제 본인이 로그인 상태에서 저장한 유효한 무료 진단과 스캔을 같은 네이버 블로그 ID로 합쳐 최신순으로 표시한다. 기존 리포트도 재진단 없이 표시되며 데이터베이스 마이그레이션이나 기록 복사가 필요하지 않다.

- 종합 점수 게이지, 5개 기준 레이더·진행 막대·분석 근거, 기간별 점수 추세, 최신 개선 항목에 같은 결과 적용.
- 분석 블로그 선택. 명시한 본인 블로그 → 진단 기록이 있는 대표 블로그 → 최근 무료 진단 → 연결 블로그 순으로 기본 대상 결정. 대표 블로그 설정은 변경하지 않는다.
- 진단 완료 팝업과 진단 기록에 해당 블로그 대시보드 링크 추가.
- 최신 결과가 무료 진단이면 그 리포트의 개선 권고를 표시한다. 과거 스캔의 완료 체크 상태와 섞지 않는다. 최신 결과가 스캔이면 저장된 할 일 상태와 완료 버튼을 유지한다.
- 선택한 블로그의 AI 인용 결과와 상세 페이지를 연결. 미연결 무료 진단에 대표 블로그의 인용 결과를 섞지 않는다.
- 무료 진단에는 글별 발행일 목록이 없으므로 최근 30일 발행 건수를 0으로 추정하지 않는다.
- 타회원·익명·만료·삭제·미래 기록은 제외. 무료 진단의 기존 30일 보관 정책 유지.
- 랭킹은 기존 대표 블로그 기준임을 제목에 표시.

## 검증

- 최종 `npm test`: 505개 통과(일반 12 + 서버 493), 실패 0. `npm run lint`, `npm run typecheck`, `npm run build` 통과.

- 실제 `diagnoseBlog()` 실행 → `buildDashboardPage()` 연결 회귀 테스트 5개 추가.
- 스캔/무료 진단 병합 순서, 기존 결과 표시, 연결 없음, 다중 블로그 선택, 이전 할 일 섞임 방지, 소유권·만료·삭제 경계 확인.
- AI 인용 선택과 상세 링크, 미연결 리포트의 인용 격리 테스트 보강.
- production Next HTTP의 `/api/mate/diagnose` POST(201) → 대시보드 SSR 확인. [HTTP 기록](http.json).
- Ego Lite에서 `/mate` 입력 → 실제 진단 API → 결과 팝업 → `대시보드에서 분석 보기` 클릭 → `?blog=visual_blog` 이동 확인.
- `visual_blog`: 95점·공개 글 9개·측정점 4개. `second_blog` 선택 시 82점·공개 글 1개·측정점 1개·발행 권고 1개로 함께 변경.
- 진단 전 대표 블로그 선택 시 점수 `-`, 측정점 0개, 첫 스캔 안내 확인.
- 1428×747 및 390×844 검증. 모바일 `scrollWidth=390`, `innerWidth=390`, 분석 기준 5개 표시.
- 사용자 서버 `127.0.0.1:3000` 유지. 별도 임시 DB, 루프백 RSS 서버, `localhost:3107`로 검증했으며 종료 후 임시 DB와 테스트 쿠키를 정리했다.

스크린샷은 격리된 테스트 RSS로 계산한 검증용 수치다.
