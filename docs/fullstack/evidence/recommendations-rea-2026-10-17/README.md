## 분석 범위와 근거

2026-10-17 원본 `/dashboard/recommendations`의 로그인 화면과 GET 응답을 Ego Lite에서 확인했다. 원본의 작성 완료·숨김 변경 요청은 실행하지 않았다. 배포 JS 3개를 REA `analyze_javascript_application`으로 분석했다. 125,292바이트, 파싱 실패 0개이며, 상세 결과는 76MB 번들로 보존했다. [증거 인덱스](rea-index.json)에 원본 URL, SHA-256, 바이트 위치와 관찰한 응답 필드를 기록했다.

전체 REA 번들: `/Users/user01/Desktop/NAEO/reverse-engineering/keyword-rea-2026-10-17/rea-bundle.json`. 계정 식별자·원본 회원 응답 전체는 저장하지 않았다.

서버 추천 알고리즘은 공개 JS로 복원할 수 없다. 화면·시그널·지표·상태 전이는 관찰을 기준으로 구현하고, 후보 생성·순위·갱신 한도는 설명 가능한 로컬 정책으로 재구성했다.

## 재구성 정책과 한계

- 수집한 본인 글의 대표 키워드·태그·주제와 겹치는 공개 키워드, 검색광고 연관 검색어를 후보로 사용한다. 공급자가 없으면 체크리스트·질문 형태의 글감을 추론하고 추천 사유에 이를 밝힌다.
- 검색량은 PC+모바일, 포화도는 문서수/검색량이다. 측정하지 않은 값은 `—`이며 임의 검색량을 만들지 않는다. 황금은 미작성·월 검색량 1,000 이상·포화도 1 이하일 때만 판정한다. 원본 가이드의 10만 상한은 최신 실응답과 달라 강제하지 않는다.
- 선점 기회는 확인된 검색량 1,000 이상·문서수 1~9,999 범위다. 인용 변화는 동일 키워드의 성공한 측정만 비교하며, 오류를 인용 소실로 간주하지 않는다.
- 무료는 30일 주기 최대 3개·월 3개, 활성 유료/체험은 7일 주기 최대 25개·월 100개, 황금 섹션은 각 3/10개다. 월 한도는 KST 달력월 기준이며 회원 전체 블로그에 적용한다. 이 수치 조합은 로컬 서비스 정책이다.
- 초기 분석 추천 이후 같은 주기에 한 번 외부 지표 보강을 허용한다. 실행 중 잠금, 만료 작업 복구, 블로그 변경·삭제 충돌 검사를 적용한다.
- 실제 네이버 자격 증명이 없는 환경에서는 외부 실측 검증을 완료했다고 주장하지 않는다. 격리 테스트의 공급자 응답은 loopback 테스트 서버이며 실제 회원 데이터와 섞이지 않는다.

## 연결 지점

- `GET /api/recommendations/feed`: 블로그·기간·검색·필터·정렬·페이지 조건별 추천
- `POST /api/recommendations/refresh`: `{blogId}`로 생성/지표 보강
- `PATCH /api/recommendations/feed/:id`: `{version,written?,dismissed?,saved?}`
- `POST /api/recommendations/feed/:id/competition`: `{version}`, 유료 경쟁 글·뉴스 조회
- 기존 `/api/recommendations`의 보관함 계약은 유지
- DB migration 48: `member_recommendations`, `recommendation_builds`. 개인정보 내보내기 및 회원/블로그 삭제 연쇄 적용
