# 관리자 목록의 100개 이후 접근 복구

2026-10-15 · 전체 페이지 CRUD 점검 중 문서·FAQ·공지 관리자가 pageSize=100 첫 페이지에 고정되어 다음 항목을 열 수 없는 문제를 확인했다. 원본 관리자 UI 역공학 결과가 아니라 클론 자체의 기능 결함이다.

## 변경

- 세 목록에 이전·다음 버튼과 현재/전체 페이지 표시를 추가했다. 처음·끝·처리 중에는 해당 버튼을 비활성화한다.
- API의 기존 page/pageSize를 전달한다. 검색 조건은 검색 버튼을 누를 때 적용하며 1페이지부터 조회한다. 아직 제출하지 않은 필터 입력은 페이지 이동에 섞이지 않는다.
- 생성 뒤에는 1페이지, 수정·삭제 뒤에는 현재 페이지를 갱신한다. 현재 페이지가 삭제로 사라졌으면 새 total에 따른 마지막 유효 페이지를 한 번 더 조회한다.
- 조회 실패는 기존 run/error 처리로 전달되고 성공한 결과만 목록에 반영한다. 권한·Origin·버전 충돌·요청 제한은 그대로 유지한다.

## 검증

API 핸들러에 연결한 격리 DB를 도메인마다 준비해 각각 101개를 생성했다. 1페이지100개+2페이지1개가 중복 없이 조회되는지, 2페이지 항목의 수정·삭제, 마지막 항목 삭제 후 실제 화면이 사용하는 loadValidPage가 2→1로 재조회하는지 확인했다.

첫 테스트는 한 관리자 세션에서 세 도메인을 연속 대량 생성하여 429 제한에 걸렸다. 제품 제한을 변경하지 않고 도메인마다 별도 DB/계정으로 분리해 통과시켰다.

전체409개(root6+server403)·lint·typecheck·production build 통과. evidence/pagination-tests.log와 pagination-build.log에 기록했다. 이 테스트는 Request/Response 핸들러 검사이며 실제 브라우저 클릭·페이지 포커스·검색 입력 유지 검증은 아니다.

## 남은 범위

RewardsManager와 EntriesReview에도 pageSize=100 고정 조회가 있어 별도로 수정·검증해야 한다. 외부 공급자·AI·전 페이지 실제 브라우저 검증 및 전체 목표는 계속 미완료다.
