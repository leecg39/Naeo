# REA 추가 범위 — 포인트·출석·튜토리얼

2026-10-15 REA 재분석의 R15-01~07/15를 구현에 반영한다. 저장소 내 발췌는 [REA 추가 근거](rea-engagement-evidence.json)에 보존했다. 원본 근거는 `../../../reverse-engineering/rea-2026-10-15/README.md`와 `evidence/findings.json`이다. 원본에서 확인한 것은 4개 API의 메서드, 5개 튜토리얼 단계·30/30/30/90/120P 상수, 클라이언트 조건이다. 서버 지급 정책·응답 필드는 복원되지 않았다.

## 구현 계약과 순서

1. 스키마 27: 토큰과 분리된 포인트 원장, 회원·KST 날짜별 출석, 회원·단계별 보상, 서브 주제·버전·변경 시각, 랭킹 방문 기록. FK cascade·UNIQUE·트랜잭션으로 중복 지급 방지. 지급된 원장 수정/삭제는 금지하고 계정 탈퇴 때만 연관 데이터를 삭제한다.
2. GET `/api/points`: 본인 잔액·페이지별 원장·오늘 출석·연속 일수·정책 반환. POST `/api/attendance`: 서버 날짜로 하루 한 번 지급, 재요청은 기존 출석 반환. 입력 금액·날짜·회원 식별자는 받지 않는다.
3. GET `/api/tutorial`: 5단계의 완료·수령 가능·잠금 이유. POST `/api/tutorial/finish` `{step}`: 서버 DB로 조건을 다시 검사하고 보상과 완료 기록을 원자적으로 저장. 재요청은 추가 지급 없이 성공.
4. 블로그 등록은 본인 블로그, 메이트는 본인 블로그의 글이 있는 유효한 메이트 진단 결과(`mate_reports`), 랭킹은 방문 기록과 서브 주제 저장이 필요하다. 공급자가 없는 AI 인용 상세·휴대폰 인증은 잠금을 유지한다. 페이지 방문만으로 이 두 단계를 보상하지 않는다.
5. 서브 주제 GET/PUT/DELETE, 낙관적 버전 충돌·변경 대기기간. 랭킹 화면에서 별도 POST로 방문을 기록하고 GET 렌더링은 상태를 바꾸지 않는다.
6. 대시보드에서 접근하는 보상 패널과 계정 설정에 출석·잔액·내역·튜토리얼 수령·서브 주제 편집을 연결한다. 새로고침·오류·중복 클릭·페이지 이동을 처리한다.
7. 격리·미동의·정지 계정·Origin·스푸핑 입력·KST 자정·연속 출석 단절·동시 지급·롤백·재시작·탈퇴·서버 props 직렬화를 검증한다. 실제 HTTP와 Ego UI 흐름으로 별도 확인한다.

## 새로 정한 로컬 정책

원본 데모 난수를 운영 규칙으로 복사하지 않는다. 이 구현은 매일 **고정 5P**, **연속 7일마다 15P**를 지급한다. KST 자정 기준이며 지나간 날 출석은 불가하다. 서브 주제 변경은 7일 대기(첫 저장은 즉시)다. 변경·삭제 모두 동일한 대기시간과 버전 검사를 적용한다. 화면·API에도 정책을 표시한다. 포인트와 AI 생성 토큰 사이의 환전은 정의하지 않는다.
