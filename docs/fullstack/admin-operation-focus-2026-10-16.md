# CRUD 성공 안내 포커스 정리

FAQ·문서·공지·이벤트·보상·참여 심사·사진함의 실제 Ego 검증에서 삭제나 회수 후 조작한 버튼이 DOM에서 사라지면 포커스가 `BODY`로 빠지는 동일한 문제가 반복됐다. `OperationNotice`는 성공 메시지가 생긴 시점에 포커스가 이미 `BODY`일 때만 안내 문단으로 옮긴다. 사용자가 다른 입력이나 버튼으로 포커스를 옮긴 경우에는 건드리지 않는다.

같은 CRUD 패턴을 사용하는 나머지 관리자 화면에도 이 동작을 적용했다.

- 스캔 상태
- 페이지 설정
- 결제·환불
- 사용자
- 키워드
- 요금제·쿠폰
- 문의 답변 템플릿
- 매거진
- 업데이트
- 문의
- 글쓰기 작업

같은 규칙을 회원·글쓰기 화면에도 적용했다.

- 개인 자료 내보내기
- 포인트·출석·시작 가이드
- 계정 보안과 세션
- 회원 결제·환불
- 소셜 로그인 연결
- 연락처·알림
- 프로필·블로그
- 연결된 외부 앱
- 초안 내보내기·사진·공유 링크·초안 작업공간

typecheck, lint, production build가 통과했다. 새 테스트는 컴포넌트 구현을 그대로 반복하는 형태가 되어 추가하지 않았다. 이 변경 이후 각 화면의 실제 삭제·취소·환불·페이지 이동 포커스는 Ego 제어권이 사용자에게 있어 실행하지 못했으므로 P11.3 브라우저 완료 근거로 계산하지 않는다.
