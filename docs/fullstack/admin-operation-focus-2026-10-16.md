# CRUD 성공 안내 포커스 정리

FAQ·문서·공지·이벤트·보상·참여 심사·사진함의 실제 Ego 검증에서 삭제나 회수 후 조작한 버튼이 DOM에서 사라지면 포커스가 `BODY`로 빠지는 동일한 문제가 반복됐다. `OperationNotice`는 성공 메시지가 생긴 시점에 포커스가 이미 `BODY`일 때만 안내 문단으로 옮긴다. 사용자가 다른 입력이나 버튼으로 포커스를 옮긴 경우에는 건드리지 않는다.

같은 CRUD 패턴을 사용하는 나머지 관리자 화면에도 이 동작을 적용했다.

- 스캔 상태
- 페이지 설정
- 결제·환불
- 사용자
- 키워드
- 요금제·쿠폰
- 문의 답변 템플릿
- 매거진
- 업데이트
- 문의
- 글쓰기 작업

같은 규칙을 회원·글쓰기 화면에도 적용했다.

- 개인 자료 내보내기
- 포인트·출석·시작 가이드
- 계정 보안과 세션
- 회원 결제·환불
- 소셜 로그인 연결
- 연락처·알림
- 프로필·블로그
- 연결된 외부 앱
- 초안 내보내기·사진·공유 링크·초안 작업공간

초기 공통 처리는 성공 안내가 나타나는 순간에만 포커스를 검사했다. 실제 관리자 환불 거절에서는 안내가 먼저 렌더되고 클릭한 버튼이 포함된 행이 나중에 제거되어 최종 포커스가 `BODY`로 빠졌다. 안내가 표시된 뒤 2초 동안 DOM 변경을 관찰하고, 활성 요소가 없거나 `BODY`이거나 DOM에서 분리된 경우에만 안내 문단으로 복원하도록 보완했다. 연결된 다른 요소에 사용자가 이동한 경우에는 포커스를 바꾸지 않는다.

101건 환불의 2페이지 마지막 행에서 실제 Ego 포인터로 거절을 다시 실행했다. 결정과 메모가 저장됐고 활성 요소는 `P[role=status]`, 텍스트는 `환불 요청을 거절했습니다.`였다. 관리자 결제·환불, 회원 결제·환불, 회원 참여·리워드의 독립 페이지 이동과 390px 포인터 검증도 함께 기록했다. [대량 목록·포커스 검증](ego-browser-list-focus-2026-10-16.md)을 P11.3 브라우저 근거로 사용한다.

수정 뒤 전체 431개 테스트, lint, typecheck, production build가 통과했다. 컴포넌트 구현을 그대로 반복하는 단위 테스트는 추가하지 않고 실제 비동기 행 제거 흐름을 브라우저 근거로 남겼다.
