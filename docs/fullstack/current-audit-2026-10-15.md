# 현재 구현·검증 상태 감사

기준 구현 커밋: 658c4b6. 전체 목표는 미완료다. 이번 실행은 기능 구현 추가가 아니라 현재 production 빌드의 접근 규칙 재검증과 남은 조건 확인이다.

## 실제 확인

- 원래 목록의83개 경로: HTTP 접근 규칙 실패0, 접근 검증76·외부 연동 대기7. 비로그인/관리자 응답을 새로 수집했다. 세션은 감사 종료까지 유지됐다.
- 별도 관리자 고정 메뉴17개: 모두 비로그인307 로그인 이동, 일반 회원403, 관리자200. 문서·FAQ·업데이트·공지·요금제·결제 메뉴도 포함한다.
- 검증은 임시 계정/격리 DB/임시 Next 서버에서 실행했고 모두 정리했다. [전체 경로 결과](page-coverage.json), [실행 및17메뉴 권한 결과](evidence/route-audit-current.json), 재실행 스크립트 `scripts/qa/route-access.ts`.
- 최근 구현의 전체417개 테스트 및 lint/typecheck/build 근거는 [이벤트 이력 검증](admin-list-pagination.md)에 있다. 이번 감사 스크립트는 eslint/typecheck를 통과했다.
- 설정 블로그 목록100개에 대해 서버 등록 상한20개를 확인했다. 초안 사진 목록20개도 업로드/연결 상한20개와 일치한다. 이 두 목록은 현재 제약 아래에서 추가 페이지 구현이 필요한 누락으로 판정하지 않았다.

`page-coverage.json`의 verified는 HTTP 접근 규칙을 통과했다는 의미다. 연결된 테스트 파일이 존재한다는 검사만으로 요구사항별 CRUD를 새로 실행했다는 뜻은 아니다. 동적 경로는 대표 표본이며 모든 입력/레코드를 검증하지 않았다. 관리자 preview 동적 경로3개는 이번17개 고정 메뉴 검사에 포함되지 않는다.

## 현재 남은 조건

| 범위 | 현재 근거 | 판정 |
|---|---|---|
| 최근 추가 UI의 Ego 클릭·hydration·모바일 | 목록 재조회 결과 NAEO 공간7/15 없음, 다른 프로젝트 공간10만 존재 | 미검증, 기존 새 공간 생성 질문 답변 필요 |
| AI 글 실제 공급자 왕복 | Anthropic 설정 필수 항목 미충족 | 미검증 |
| AI 이미지·AI 인용 근거 | 사용자는 OAuth 선택. 공식 OAuth 경로는 이미지 생성 미지원, 인용 근거도 별도 검증 필요 | 미완료 |
| 토스 실제 샌드박스 | 필수 키 설정 미충족 | 미검증 |
| Google/네이버 실제 로그인 | 두 공급자 모두 필수 설정 미충족 | 미검증 |
| 메일/SMS 실제 수신 | 두 공급자 모두 필수 설정 미충족 | 미검증 |
| 실제 확장 프로그램 | 허용 확장 ID 설정 미충족, 기존 코드 부재 과제 유지 | 미검증 |
| 전 페이지 최종 완료 | 위 조건과 P11.3 등 체크 미완료 | 완료 처리 불가 |

설정 확인은 현재 프로세스와 Next production env 파일의 필수 항목 존재 여부만 검사했다. 외부 계정이 존재하지 않는다는 주장은 아니며 자격 증명 값은 출력·기록하지 않았다. [설정 존재 여부](evidence/provider-readiness-current.json).

Ego 스킬의 “Never use a new TaskSpace to recover … stop and ask the user.”에 따라 다른 프로젝트 공간을 사용하거나 대체 공간을 만들지 않았다. OpenAI 키 선택 질문은 OAuth 선택으로 답변됐다. [OAuth 적용 범위와 실행 항목](openai-oauth.md)에 공식 지원 조건을 기록했다. 회원별 배포 서비스로 확정됐으며, 해당 용도의 클라이언트 승인·사용량 위임 권한·HTTPS 콜백 조건이 필요하다. 위 외부 연결·화면 검증 없이는 원래 목표를 달성했다고 표시하지 않는다.

## 감사 기록 보존 수정

재실행 과정에서 route-audit가 evidence 배열을 통째로 바꿔 기존 browser-render83건을 제거하는 문제가 확인됐다. HTTP/tests/verification/external_pending만 새 결과로 교체하고, 그 외 근거는 보존하도록 수정했다. 이전 브라우저 기록의 시각과 내용은 유지했으며 이번 브라우저 검증으로 표현하지 않는다. 재실행 뒤 원본83건과 내용 일치를 검사했다.

## 관리자 미리보기3종 추가 검증

앞의17개 고정 메뉴에서 제외했던 `/admin/pages/preview/[id]`, `/admin/blog/preview/[id]`, `/admin/updates/preview/[id]`를 별도 production HTTP 시나리오로 검증했다. 임시 DB에 관리자·일반 회원 계정을 만들고 API로 초안을 생성했다.

각 종류에서 초안 미리보기200·실제 본문, 비로그인307·회원403, noindex 메타, 공개 페이지의 초안 비노출을 확인했다. 이어서 본문 수정→미리보기 반영, 이전 버전 수정409, 발행→공개 화면 반영, 삭제→공개 화면 제거를 확인했다. 삭제된 ID·없는 UUID·잘못된 ID는 모두404였다. HTML 검사는 script/style을 제거한 실제 마크업 텍스트를 사용해 RSC 직렬화 문자열만으로 본문 반영을 판단하지 않았다.

[실행 결과](evidence/preview-crud-runtime.json), 재실행 스크립트 `scripts/qa/preview-crud.ts`. 스크립트 eslint·typecheck 통과. 기존 앱 코드는 수정할 필요가 없었고 임시 서버·DB를 정리했다. 브라우저 화면·클릭·모바일 증거는 아니다. 기존 전체417개 테스트 결과는 이전 실행 시점의 근거이며, 이번에 전체 테스트를 다시 실행했다고 표현하지 않는다.
