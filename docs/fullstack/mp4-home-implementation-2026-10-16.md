# MP4 내보내기·홈 런타임 복원 — 2026-10-16

사용자의 REA 후속 구현 요청에 따라 기존 `unsupported`였던 MP4를 지원하고, 홈의 멈춘 랭킹과 숨겨진 글쓰기 예시를 복원했다. [구현 전 조사](rea-mp4-drift-2026-10-16.md)의 MP4 판정은 이 문서와 [API 계약 P7.5](api-contracts.md#p75-내보내기미리보기-2026-10-14)로 대체한다. 배포·커밋·푸시는 수행하지 않았다.

## MP4 구현

- 브라우저가 기존 SVG를 PNG 장면으로 렌더링해 전송하고, 서버 작업자가 FFmpeg `libx264`로 인코딩한다. 한글·이미지·프로젝트 장면 순서를 보존한다.
- 원본 프로젝트 크기(1920×1080, 1080×1350, 1080×1440), H.264/yuv420p, 30fps. 무음 정지 장면이며 전환 효과는 없다. 장당 1~30초(기본 3초), 최대 20장·600초다.
- `collecting → queued → encoding → succeeded/failed/canceled`. 화면에 업로드·대기·진행률·실패·취소·다운로드를 표시하고, 업로드 완료 후에는 화면을 떠나도 작업자가 처리한다. 새로고침하면 서버 상태를 다시 읽는다.
- 스키마 45로 PDF/ZIP 작업과 페이지 참조를 보존하면서 MP4·상태·진행률·임대 필드를 추가했다. 인코더 부재는 503, 큐 한도 초과는 429다.
- DB당 인코더 한 개, 회원별 활성 MP4 2개·전체 32개. 30초 임대·1초 갱신, 비정상 종료 최대 3회 복구, 정상 종료는 대기 상태로 복귀한다. 취소·프로젝트 삭제·회원 삭제 이후 늦은 결과가 공개되지 않도록 소유권과 임대 토큰을 다시 검사한다.
- 작업당 5분·256MB 제한, CPU 스레드 제한, 셸 없이 프로세스 실행, 비공개 임시 경로·파일 권한, 실패·취소·만료 정리. 완성 파일은 7일 보관한다. 개인정보 이동성 TAR은 MP4와 진행 중 입력 PNG를 포함한다.

핵심 파일: `src/server/creative/{exports,mp4,worker,creative-api}.ts`, `src/components/creative/ExportPanel.tsx`, `scripts/worker.ts`. 웹과 worker에 FFmpeg/libx264가 필요하며 `NAEO_FFMPEG_PATH`가 비어 있으면 PATH에서 찾는다. 같은 DB·업로드 폴더로 `npm run worker`를 실행한다. 상세는 [운영 문서](operations.md#mp4-내보내기-스키마-45)를 따른다.

## 홈 복원

기존 홈 JSON에는 12개 섹션과 14개 이미지가 이미 있었다. 네 이미지는 숨겨진 글쓰기 예시 안에 있었고, 랭킹은 수집 시점의 로딩 상태에 머물렀다. 별도 신규 섹션이나 이미지 파일을 원본에서 추가로 가져오지 않았다.

- 로딩 랭킹을 실제 공개 동의 회원의 `liveRanking`으로 교체했다. 데이터가 없으면 0명 빈 상태를 표시한다. 점수는 블로그 진단 점수임을 밝히며 AI 인용 횟수로 표시하지 않는다.
- 기존 패널을 키워드 선택 → AI 작성 → 완성 글 → 모바일 미리보기 → 발행 예시의 5단계로 연결했다. 자동 재생·수동 선택·일시정지, 숨김 패널의 접근성 처리, 화면 밖/포인터/포커스에 따른 재생 중지, 동작 줄이기 설정을 지원한다.
- 완성 글과 휴대폰 미리보기의 이미지·내부 스크롤을 복원했다. 일반 랜딩 애니메이션이 숨긴 패널을 다시 노출하지 않도록 제외했다.
- ChatGPT·Claude 선택에 따라 표시 제목·예시 텍스트·이미지 도구 행을 갱신한다. 이 영역은 설명용 예시이며 실제 글 생성·발행을 수행하지 않는다.

원본의 모든 타이핑·커서·미세 전환 애니메이션을 재현한 것은 아니다. 실제 신규 섹션으로 확인된 upstream drift를 자동 복사하지 않는 원칙은 유지한다. 핵심 파일은 `src/components/home/{home-page,home-demo,home-styles}.ts`, `src/app/page.tsx`, `src/behaviors/landing.tsx`다.

전체 테스트 중 기존 검색 지표 테스트가 실제 현재 시각과 고정 수집 시각을 섞어 순서에 따라 실패했다. 수동 입력 시각을 고정 기준 직전으로 지정해 의도한 순서를 검증하도록 수정했고, 제품 로직은 바꾸지 않았다.

브라우저 검증은 별도 DB·업로드 경로·호스트의 프로덕션 서버와 Ego TaskSpace 6에서 수행했다. 원본 사이트는 읽기 전용으로 관찰했다. 검증 후 해당 TaskSpace와 임시 worker·웹 서버를 종료했다.
