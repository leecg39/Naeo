# 사진 마크다운 링크 구현 및 검증

## 구현

원본 `/images` 번들에서 확인한 계약에 맞춰 `/api/images` 업로드를 추가했다. 응답은 `url`, `markdown`, `media`를 반환한다. 사진함은 사진별 복사와 현재 페이지 전체 복사를 제공한다.

공개 주소는 개인 `publicId`와 다른 22자 무작위 토큰을 사용한다. `media_markdown_links`가 토큰과 사진을 연결하며 다음 조건을 지킨다.

- 개인 `/api/media/{publicId}`는 계속 로그인한 소유자만 읽는다.
- `/api/images/{token}`은 토큰을 아는 사람만 해당 사진 한 장을 읽는다.
- 다른 사진의 개인 ID를 토큰 자리에 넣어도 404다.
- 같은 사진의 링크 발행은 멱등이다.
- 소유자가 사진을 삭제하면 외래 키 CASCADE로 토큰도 삭제되어 기존 URL이 즉시 404가 된다.
- 사진은 보관한 채 `공개 링크 끄기`로 토큰만 폐기할 수 있다. 다시 복사하면 이전 값과 다른 새 토큰을 만든다.
- 공개 이미지 응답은 `Cache-Control: no-store`다. 장기 immutable 캐시가 폐기된 링크의 사진을 계속 표시하지 않게 한다.
- 서버 파일 읽기는 기존 no-follow·크기·MIME 검증을 그대로 사용한다.

기존 사진 중 링크가 없는 항목은 최초 복사 때 소유권을 확인한 뒤 토큰을 만든다. 사진함에서 올린 사진은 업로드 응답과 목록에 즉시 링크 토큰이 포함된다. 초안에 직접 첨부한 사진은 개인 `/api/media` 흐름을 유지한다.

## 검증

- 신규 migration 37 적용.
- 단위 테스트: 토큰 멱등성, 소유자 격리, 개인 ID 비공개, 단일 사진 공개, 명시적 폐기·재발행, 삭제 후 폐기.
- HTTP 테스트: `/api/images` 인증 업로드, 정확한 URL·마크다운 응답, 익명 조회, 개인 ID 거부, 목록 토큰, 링크 폐기·새 토큰 재발행, 사진 삭제 후 404.
- 별도 프로덕션 서버에서 Ego 파일 입력으로 2400×1200 PNG를 업로드했고, 저장 결과가 `wide.jpg`, JPEG, 1600×800이며 공개 토큰이 생성됨을 DB와 실제 파일로 확인했다.
- 별도 HTTP 런타임에서 업로드 201, 익명 공개 조회 200, 개인 조회 무인증 401, 소유자 삭제 200, 삭제 후 공개 조회 404를 확인했다.
- build, typecheck, lint 통과. 최종 전체 검증은 루트 6개와 서버 417개 테스트가 모두 통과했다.

[증거 폴더](evidence/ego-image-markdown-2026-10-16/)

Ego에서 복사 버튼을 누르는 단계에서 TaskSpace 제어권이 사용자에게 넘어가 클립보드 문자열을 읽는 검증은 완료하지 못했다. 제어권을 우회하지 않았다. 확장 프로그램이 이 마크다운을 받아 실제 네이버 에디터에 발행하는 종단 검증도 남아 있으므로 P11.8 전체 완료로 처리하지 않는다.
