# Ego 대량 목록·CRUD·포커스 검증

2026-10-16

운영 데이터와 분리한 SQLite 데이터베이스에 관리자 회원, 쿠폰·결제·환불·이벤트·참여·리워드를 각각 101건 만들고, production build를 `127.0.0.1:62570`에서 실행했다. Ego Lite의 기존 `NAEO 클론 화면` 공간과 로그인 세션을 사용했으며 다른 사용자 탭은 조작하지 않았다.

## 실제 확인 결과

- 관리자 요금제·쿠폰: 101건의 2페이지 이동과 마지막 쿠폰 중지를 확인했다. 중지된 쿠폰은 감사 기록으로 남아 2페이지가 유지됐다.
- 관리자 결제·환불: 환불과 결제가 각각 101건인 상태에서 두 페이지가 서로 독립적으로 유지됐다. 마지막 환불에 메모를 입력하고 `거절`을 눌러 상태와 메모 저장을 확인했다. 결제 2페이지의 `browser-order-100`을 확인하고 같은 주문 번호와 `결제 완료` 상태 검색 결과가 1건·1페이지로 줄어드는 것도 확인했다.
- 회원 계정 설정: 결제와 환불이 각각 101건일 때 두 목록이 서로 독립적으로 3페이지까지 이동했고 마지막 페이지에 각각 1건이 나타났다.
- 회원 이벤트: 참여와 리워드가 각각 101건일 때 두 목록의 2페이지에 각각 1건이 나타났다. 참여만 이전 페이지로 이동했을 때 리워드는 2페이지를 유지했고, 이어 리워드만 이전 페이지로 이동해 각각 100건인 첫 페이지를 확인했다.
- 모바일: 390×844에서 관리자 결제·환불 문서 폭과 화면 폭이 같아 가로 넘침이 0이었다. 환불 페이지의 `다음` 버튼을 실제 포인터로 눌러 2/2와 마지막 1건을 확인했다.

## 발견하고 수정한 결함

환불 거절 버튼을 누른 뒤 목록 행이 비동기로 다시 그려질 때, 성공 안내가 먼저 렌더되고 클릭한 버튼이 나중에 제거됐다. 기존 `OperationNotice`는 안내가 생긴 순간에만 `document.body` 포커스를 검사해서 이 순서에서는 최종 포커스가 `BODY`에 남았다.

안내가 표시된 뒤 2초 동안 DOM 변경을 관찰하고, 활성 요소가 없거나 `BODY`이거나 DOM에서 분리된 경우에만 안내 문단으로 포커스를 복원하도록 바꿨다. 사용자가 다른 연결된 입력이나 버튼으로 이동한 경우에는 포커스를 빼앗지 않는다. 같은 환불 거절 흐름을 다시 실행한 결과 활성 요소는 `P[role=status]`, 텍스트는 `환불 요청을 거절했습니다.`였고 저장된 행은 `거절 / Ego 실제 거절 검증`으로 표시됐다.

세부 값은 [Ego 실행 요약](evidence/ego-browser-list-focus-2026-10-16/summary.json)에 기록했다. 화면 캡처는 검증 중 Ego 창이 최소화된 상태라 생성하지 못했으며, DOM 상태·실제 포인터 좌표·저장 결과를 같은 브라우저 세션에서 확인했다.

수정 뒤 확장·화면 계약 12개와 서버 419개, 합계 431개 테스트가 모두 통과했다. lint, typecheck, production build도 통과했다.

## 범위

이 검증은 P11.3의 대량 목록 조합을 추가로 채운 것이다. 보상·참여 심사의 390px 실제 포인터 조합과 아직 실행하지 않은 목록 조합은 계속 남겨 둔다. 결제사 취소가 필요한 실제 승인 환불은 결제 공급자 키가 없는 격리 환경에서 실행하지 않았다.
