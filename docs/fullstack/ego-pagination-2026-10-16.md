# Ego 대량 목록 검증 — FAQ·문서·공지

2026-10-16. 사용자 재개 요청에 따라 Ego 공간15 제어권을 가져왔다. 기존 NAEO 탭을 p1으로 채택했으며 다른 세 탭은 조작하지 않았다.

## 실행과 확인

테스트용 관리자와 도메인 서비스로 비공개 FAQ·문서·공지를 각각101건 만들었다. 데이터 준비는 서비스 호출이며, 아래 조회·검색·편집·삭제는 Ego 화면에서 직접 수행했다.

| 목록 | 실제 화면 확인 |
|---|---|
| FAQ | 검색101건 → 다음 → 101번째 항목 조회 → 질문 수정/저장 → 삭제 확인 →100건·1/1페이지 복귀. 페이지 표시에서 Shift+Tab으로 이전 버튼 접근 |
| 문서 | 검색101건 → 검색창에 미제출 문자열 입력 → 다음에서도 기존 적용 조건 유지 →101번째 제목 수정/저장 → 주소 입력 확인 후 삭제 →100건·1/1페이지 복귀 |
| 공지 | 검색101건 → 다음 → 마지막 항목 삭제 확인 →100건·1/1페이지 복귀 |
| 390px 모바일 | 세 목록에서 마지막 페이지 삭제·복귀 및 성공 안내 포커스 확인. documentElement.scrollWidth가 innerWidth를 넘지 않음. 표는 내부 가로 스크롤 사용 |

## 발견한 오류와 수정

FAQ에서 편집기가 삭제 후 사라질 때 키보드 포커스가 BODY로 빠졌다. 세 목록이 공통 `OperationNotice`를 사용하도록 수정했다. 성공 메시지 렌더 후 포커스가 BODY에 있을 때만 안내로 이동한다. 다른 입력에 있는 포커스를 가져오지 않으며 tabIndex=-1로 일반 탭 순서에는 추가하지 않는다.

수정 뒤 FAQ·문서·공지 각각에서 성공 안내 문구에 포커스가 놓이고100건·1/1페이지인 상태를 실제 Ego로 확인했다. [증거 폴더](evidence/ego-pagination-2026-10-16)에는 JSON 상태와 모바일 스크린샷을 저장했다. 문서 모바일 스크린샷은 이미지 뷰어로 열어 확인했다.

문서 검증 초기에 페이지의 모든 표 행을 합산해 기대값을 넘기는 검증 스크립트 오류가 있었다. 고정 디자인 페이지 표3행이 별도로 있어 첫 정책 문서 표로 범위를 좁혔다. 또한 수정 중 열린 문서 탭의 이전 코드에서는 안내에 tabindex가 없었다. 새로고침 후 최신 코드를 로드해 재검증했다. 이를 제품의 페이지 이동 실패로 기록하지 않는다.

## 정리 및 한계

- 마지막 테스트 후 fixture ID 목록에 포함된 데이터만 도메인 삭제 서비스로 정리했다. 각 종류 남은 테스트 레코드0: [정리 결과](evidence/ego-pagination-2026-10-16/cleanup.json). 기존 사용자 데이터와 감사 기록은 유지했다.
- 타입 검사·린트 통과. 전체 서버420개가 아니라 이전 전체 테스트420개(기본6+서버414)가 마지막 전체 실행이다. 이번 UI 변경 후 전체 서버 테스트를 다시 실행한 것으로 표현하지 않는다.
- 이벤트 선택기/참여·리워드·쿠폰·결제/환불·사진함 등의 대량 목록 브라우저 검증은 남아 있다. P11.3 전체를 완료 처리하지 않는다.
- 생성은 데이터 준비용 서비스 호출이었다. 이번 대량 검증을 모든 항목의 브라우저 생성 검증으로 표현하지 않는다. 일반 생성 CRUD는 이전 Ego 보고서에서 별도로 추적한다.
