# 결제·환불 중단 복구 — 2026-10-15

기존 P9.2 초안 11개를 현재 코드에서 실행해 **11개 실패**를 다시 확인한 뒤 수정했다. 결과를 통과시키기 위해 기존 실패 사례를 삭제하지 않았다. 강제 종료 사례의 DB 준비 코드에는 새 버전이 실제로 저장하는 최초 요청 시각과 취소 전 누적액을 추가했다. 추가 경계 사례와 업그레이드를 포함한 전용 테스트는 20개다.

## 계약 근거

- [토스 Payment 객체](https://docs.tosspayments.com/reference): 거래 식별자·주문 번호·총액·취소 가능한 잔액·상태를 대조한다. 환불 사유는 문서의 200자 범위로 제한했다.
- [토스 멱등키 정책](https://docs.tosspayments.com/reference/using-api/authorization): 최초 사용 이후 15일, 같은 요청의 키를 유지해야 한다. 보존 기간이 지난 불확정 거래에는 금액을 바꾸는 API를 다시 보내지 않고 조회만 수행한다.
- [멱등 요청의 처리 중 오류](https://docs.tosspayments.com/blog/what-is-idempotency): 동시 처리·네트워크 오류를 확정 거절로 판단하지 않는다.

토스는 이 프로젝트가 선택한 공급자다. 원본 NAEO의 Payple 서버를 복원했다고 주장하지 않는다.

## 구현

| 영역 | 이전 문제 | 변경된 동작 |
|---|---|---|
| 승인 중 주문 | await 동안 새 주문/만료/취소로 덮어쓰기 | 공급자 호출 전에 `payment_key`, `confirm_started_at` 저장. 해당 주문의 키는 불변이며 결과 미확정 동안 교체·로컬 만료·클라이언트 취소로 확정하지 않음 |
| 승인 응답 | 키 대조 누락·불일치 기록 롤백 | 키/주문/금액/잔액/상태 검사. 미확정 결과를 ready로 보존하고 오류 기록을 별도 커밋 |
| 서버·응답 유실 | 거래 결과 조회 경로 부족 | 회원·관리자 재조회 API와 UI. 같은 승인 재시도는 원래 멱등키, 15일 이후 조회만 |
| 탈퇴 | 외부 승인 뒤 사용자 FK 오류 | 금융 기록을 user_id NULL로 보존하고 구독/회원 데이터는 재생성하지 않음 |
| 웹훅 | 다른 거래의 상태/비정상 잔액 적용 | 실제 공급자 조회의 식별자·잔액·상태 검사, 이벤트 전체 식별값의 SHA-256으로 중복 구분. 늦은 DONE은 이미 취소된 주문을 되돌리지 않음 |
| 환불 | 누적액만 보고 완료·일반 통신 오류 방치 | 최초 취소 전 누적액과 요청 시각을 저장. 동일 거래에서 정확히 요청액만큼 취소됐는지 확인 후 완료 |
| 환불 재시도 | failed 뒤 새 환불·프로세스 중단 뒤 approved 고착 | 실패도 미확정 요청으로 잠금. 60초 뒤 동일 ID/멱등키로 재개하고 version으로 늦은 응답을 차단 |
| 환불 거절 | 이미 외부 요청한 환불을 거절할 수 있음 | requested만 거절 가능. 외부 취소를 시도한 환불은 같은 요청으로 먼저 확인 |
| 공급자 미설정 | 관리자 요청이 저장된 채 남음 | 공급자 검사 후 요청 생성 |

스키마 28은 새 필드와 요청 불변 트리거를 추가한다. **이전 버전에서 미확정인 환불은 취소 전 누적액을 알 수 없어 자동으로 값을 만들어 넣지 않는다.** `REFUND_RECONCILIATION_REQUIRED`로 표시하고 결제사 거래 내역 대조를 요구한다. 기존 결제·환불 금액과 상태는 마이그레이션에서 변경하지 않는다.

## UI와 API

- `/dashboard/settings#billing`: 확인 중인 주문 표시, 결제사 상태 조회, 같은 결제 승인 재시도.
- `/payment/complete`: 결과 불명인 거래를 결제 실패로 단정하지 않고 확인 중으로 표시.
- `/admin/payments`: 결제사 상태 조회, 실패/중단 환불의 동일 요청 재처리.
- `POST /api/billing/payments/:orderId/reconcile`: 본인 주문만, Origin·로그인·약관 검사. 공급자 GET 결과를 반영한다.
- `POST /api/admin/payments/:paymentId/reconcile`: 관리자만, 탈퇴 회원의 금융 기록도 조회해 정리할 수 있다.
