# 인증된 휴대폰 번호의 120P 보상 — 스키마 33

2026-10-15 · P10.4 부분 구현. REA에서 확인한 휴대폰 인증 단계 120P 및 동일 번호 중복 수령 안내를 반영했다. 원본 서버의 저장 방식·보관 기간·중복 판정은 공개되지 않아 아래 HMAC·트랜잭션 정책은 클론의 별도 설계다.

## 승인 근거와 수령

SMS 공급자 코드 확인이 승인되면 연락처 인증 시각과 `verified_phones`의 정규화 번호/승인 시각을 같은 트랜잭션에 기록한다. OTP와 공급자 응답 본문은 보존하지 않는다. 연락처의 인증 시각만 있고 승인 근거가 없으면 보상 자격이 없다. 스키마 32 이전 인증도 자동 소급 증명하지 않으므로 필요한 경우 재인증한다. 설정에서 이미 인증한 번호도 다시 확인할 수 있다.

기존 시작 가이드의 휴대폰 단계가 자격을 표시하고 POST `/api/tutorial/finish` `{step:"verify"}`로 수령한다. 활성 계정·약관·공급자 승인 근거·현재 정규화 번호·현재 인증 시각·미수령 상태를 검사한다. 같은 계정의 재요청은 0P와 기존 수령 상태를 반환한다. 번호를 바꿔도 계정당 휴대폰 단계는 한 번만 받을 수 있다.

## 중복 방지·원자성

국내 010 번호와 같은 번호의 +82 표기를 동일하게 정규화한다. `NAEO_PHONE_REWARD_KEY`(32바이트 hex)로 domain-separated HMAC-SHA256 지문을 계산한다. `phone_reward_registry`에는 지문과 지급 시각만 저장하며 사용자 ID·전화번호 원문은 넣지 않는다.

번호 지문 예약, 최초 키 digest 고정, tutorial 수령 기록, 포인트 원장 +120P를 하나의 BEGIN IMMEDIATE 트랜잭션으로 처리한다. 지문 PRIMARY KEY와 계정별 단계 UNIQUE가 중복 지급을 막는다. 중간 실패는 모두 롤백한다. 이미 다른 계정이 수령한 번호는 해당 계정의 신원을 공개하지 않고 잠금 안내를 반환한다.

계정 삭제는 본인 연락처·승인 근거·포인트 원장을 제거하지만 번호 지문은 남는다. 같은 번호의 탈퇴 후 재가입·다른 계정 재수령도 차단한다. 이 지문은 완전 익명이라고 주장하지 않는다. 서비스는 동일 번호를 다시 판별할 수 있다. 이 보존 동작을 회원 탈퇴 화면에 안내했다. 지문 기록과 키 binding은 일반 UPDATE/DELETE를 DB trigger로 막는다.

## 키 운영

`openssl rand -hex 32`로 별도 키를 만들고 웹 서버에 `NAEO_PHONE_REWARD_KEY`로 제공한다. `.env.example`에는 빈 값만 있다. 키가 없으면 SMS 인증은 가능하지만 보상은 잠긴다. 첫 지급 후 DB에 key digest가 고정되며 다른 키를 넣으면 추가 지급을 중단한다. 키 변경으로 중복 지급 검사가 리셋되는 상황을 막는 장치다.

키는 DB와 별도 비밀 저장소에 백업해야 한다. 원래 키를 복원하면 기존 지문을 계속 확인한다. 기존 번호 원문이 없는 지문을 새 키로 자동 변환하는 기능은 없다. 키 손실 시 신규 키로 임의 초기화하지 않는다. 원본 서비스의 키 정책이라고 표현하지 않는다.

## 검증

- 신규 6개·전체 395개(기반 6 + 서버 389) 테스트. lint/typecheck/build 통과.
- 승인 없이 timestamp만 설정한 계정 거절, 120P 한 번 지급/재요청 0P, 표기 다른 같은 번호의 타 계정 거절, 원래 계정 삭제 후 거절.
- 번호 변경/연락처 삭제에 따른 승인 근거 폐기, 같은 계정의 추가 번호 수령 차단.
- 원장 insert 강제 실패 시 registry/key binding/수령 기록 전부 롤백, 재시도 정상 지급.
- 키 누락·교체 시 차단, 원래 키 복원, registry/key binding 변조 차단.
- 실제 독립 Node 프로세스 2개가 한 SQLite DB의 동일 인증 번호로 동시에 수령: 지급 합계 120P, 지문 1개, 다른 프로세스 TUTORIAL_LOCKED.
- 실제 production Next + loopback SMS 공급자: 인증 승인→120P 수령→재요청 0P→같은 번호를 인증한 두 번째 계정 409. 기존 SMS 오답·번호 변경·로그아웃 회귀 포함.
- 개인 데이터 export는 본인 승인 근거를 추가해 45개 데이터셋이며 서비스 공통 지문/키 digest는 포함하지 않는다.

실행 로그·코드 해시·HTTP 결과는 `evidence/phone-reward-*`에 보존한다. 외부 SMS 전송·실제 단말 수신·Ego 클릭/시각 비교는 미검증이다. AI 인용 단계와 외부 검증이 남아 총 300P 전체 기능 완료 및 P10.4 전체 완료로 표시하지 않는다.
