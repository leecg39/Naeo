# 사진 업로드 1600px 최적화 구현 및 검증

## 근거와 구현 선택

REA 저장 화면 `docs/research/naeo.kr/runtime-images-1440.json`에 “자동 1600px 최적화” 안내가 있다. 기존 사진 업로드는 원본 바이트를 그대로 전송했다. 원본의 정확한 변환 알고리즘은 확보하지 못했다. 구현은 비율을 보존하며 긴 변을 1600px 이하로 줄이는 방식을 선택했다(원본 알고리즘과 동일하다는 주장은 아님).

공통 uploadPhoto에 preparePhoto를 연결했다. 사진함·초안 첨부·글쓰기 업로드에 적용된다. 10MB 초과 및 지원하지 않는 MIME을 거절하고, 브라우저에서 디코딩하지 못한 사진도 거절한다. 큰 사진은 Canvas로 원래 MIME을 요청해 변환하며 PNG 투명도를 유지한다. 작은 사진은 변환 없이 원본을 전송한다. 비트맵은 finally에서 해제한다. 서버의 크기·서명·소유권·수량 검사는 계속 적용된다. 직접 API 호출에 1600px 제한을 강제하는 서버 변환은 추가하지 않았다.

## 실제 검증

별도 DB·업로드 폴더·프로덕션 서버를 사용해 Ego 파일 입력으로 세 이미지를 올렸다. 화면의 naturalWidth/Height와 실제 저장 파일을 모두 확인했다.

- PNG 2400×1200 → 1600×800, alpha 유지.
- JPEG 900×2700 → 533×1600.
- WEBP 320×240 → 동일 크기, 원본 바이트 동일.
- 손상 PNG → 읽기 오류 표시, 기존 3장 그대로 유지.
- build 및 lint 통과. 전체 테스트 재실행은 하지 않았다.
- 검증 후 임시 서버·DB·업로드 파일·자격증명을 정리했다.
