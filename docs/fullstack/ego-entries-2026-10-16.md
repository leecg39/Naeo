# Ego 참여 심사 검증 — 2026-10-16

기존 Ego TaskSpace 0 / p1에서 임시 SQLite DB 및 별도 localhost 프로덕션 서버로 검증했다. 101명·101개 참여는 서비스 함수로 준비했다. 참여 생성 UI 검증을 의미하지 않는다.

## 재현 및 수정

심사 대기 필터 → 목록 다음 페이지 → 마지막 참여의 메모 입력 및 승인 버튼 클릭을 수행했다. 승인 후 100건·1/1페이지로 정상 복귀했지만 포커스가 BODY로 빠졌다. EntriesReview에 기존 OperationNotice를 적용했다.

## 수정 후 실제 검증

- 대기 참여를 101건으로 보충한 뒤 새 프로덕션 빌드에서 다시 마지막 행을 승인했다. 1440px 화면에서 100건·1/1페이지 및 성공 안내 포커스를 확인했다.
- 승인 필터로 두 참여를 조회했다. 390px 화면에서 Enter 키로 각각 반려해 0건·빈 목록·1/1페이지 및 성공 안내 포커스를 확인했다.
- 후속 검증에서 101건의 심사 대기 목록을 다시 준비하고 390px에서 `다음`을 실제 포인터로 눌러 마지막 한 건에 도달했다. 테이블을 가로로 이동한 뒤 메모를 입력하고 `승인`을 실제 포인터로 눌렀다. 대기 목록은 100건·1/1페이지로 복귀했고 성공 안내 `P[role=status]`가 포커스를 받았다. DB에는 `approved`, 버전2, 메모 `390px 포인터 승인 검증`이 저장됐다.
- DB 읽기 검증으로 두 회원 모두 승인 +15토큰, 반려 -15토큰이 각각 한 번씩 기록됨을 확인했다. 심사 메모 저장도 확인했다.
- 빌드, 린트 및 이벤트 서버 테스트 10개 통과. 전체 테스트는 재실행하지 않았다.
- 임시 서버 종료, 임시 DB·자격증명 삭제 후 원래 3000 포트 참여 심사 화면으로 복귀했다.
