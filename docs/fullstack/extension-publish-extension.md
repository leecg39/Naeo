# 네이버 블로그 발행 확장 구현

2026-10-16

## REA에서 확인한 계약

원본 `/guide/extension-publish`는 자동 입력이나 자동 발행을 하지 않는다. 회원이 NAEO에 저장한 글을 선택하면 확장이 제목·본문·사진·소제목 행을 보여주고, 행을 누를 때 클립보드에 해당 조각을 넣거나 편집기의 해당 줄을 선택한다. 회원은 직접 붙여넣고 네이버 툴바의 소제목 서식을 고른 뒤 발행 버튼을 누른다.

이 경계를 유지했다. 확장은 네이버 계정 비밀번호·키 입력·발행 버튼을 조작하지 않는다.

## 구현

`extension/`은 별도 빌드가 필요 없는 Manifest V3 확장이다.

- Manifest 공개키로 로컬 개발 ID `lacdnccodopejadkbeannbcmbljiodik`를 고정했다.
- 회원이 입력한 NAEO 루트 주소만 허용한다. 배포 주소는 HTTPS, HTTP는 localhost·loopback만 가능하다.
- 사용자 동작으로 해당 서버의 선택적 host permission을 요청한다.
- `chrome.identity.launchWebAuthFlow`와 S256 PKCE로 `/auth/extension`에 연결한다.
- 접근·회전 리프레시 토큰은 `chrome.storage.local`에 보관하고, 연결 해제 시 서버 토큰 계열을 철회한다.
- MCP `naeo_list_drafts`, `naeo_get_draft`를 사용해 최근 초안과 본문을 가져온다.
- 원본 안내대로 서버가 최근 저장 시각부터 30일 뒤 초안·수정 이력·글 공유 링크를 자동 삭제한다. 사진은 기존 수동 삭제 정책과 같이 사진함에 남으며, 확장 목록에 자동 삭제 날짜를 표시한다.
- 마크다운을 제목·본문·소제목·사진 행으로 분해한다. 본문 복사는 `text/plain`과 안전하게 이스케이프한 `text/html`을 함께 제공해 표·인용구·목록·줄바꿈을 보존한다.
- 글 맨 위의 이미지만 대표 사진으로 판단해 본문보다 먼저 처리하고 본문에는 중복 표식을 넣지 않는다. 나머지 이미지 자리는 `〔NAEO 사진 N: 대체 텍스트〕` 표식으로 남긴다. 사진 행은 공개 링크를 가져와 PNG 클립보드 이미지로 변환한 뒤 해당 표식을 선택한다.
- 네이버 글쓰기 활성 탭의 모든 허용 프레임에서 제목 입력란, 가장 큰 본문 편집기, 사진 표식, 소제목 텍스트를 찾는다. 위치를 찾지 못하면 적용 완료로 기록하지 않는다.
- 행 진행 상태는 초안별로 로컬 저장하며 초기화할 수 있다.

확장 설치·권한 경계·서버 환경 변수는 [`extension/README.md`](../../extension/README.md)에 기록했다.

## 검증

- 순수 모듈 테스트 5개: 서버 URL 제한, Manifest 키에서 고정 ID 계산, PKCE S256, 마크다운 구조/이스케이프, MCP 성공·오류 응답.
- Chrome `--pack-extension`으로 Manifest와 전체 확장 패키징 성공.
- 실제 Next 서버와 격리 DB에서 회원 로그인 → `/auth/extension` 307 → 동의 화면 200 → 승인 200 → 토큰 200 → 확장 Origin의 MCP 초안 검색 200 → 리프레시 토큰 철회 200 → 기존 접근 토큰 401을 확인했다. 토큰 원문은 기록하지 않았다. [HTTP 근거](evidence/extension-e2e-2026-10-16/http-oauth-mcp.json).
- Ego의 `/images`에서 운영체제 붙여넣기로 공개 이미지 마크다운 문자열을 확인했다. 같은 링크는 200, `공개 링크 끄기` 후 404, 성공 안내 포커스 복원, 재복사한 다른 토큰은 200이었다.

## 남은 검증

Ego 확장 관리 화면에서 개발자 모드와 폴더 선택 단계까지 진행했다. macOS 폴더 선택 대화상자는 사용자가 처리해야 한다. 로드 후 실제 사이드 패널에서 OAuth 동의·초안 선택·텍스트/서식/사진 클립보드·네이버 편집기 위치 선택·연결 해제를 직접 확인해야 한다. 실제 게시물 발행은 외부 공개 변경이므로 회원이 직접 눌러야 한다.

Chrome Web Store에는 아직 등록하지 않았다. 스토어가 부여한 ID, 배포 서버의 `NAEO_EXTENSION_IDS`, 개인정보처리방침과 심사를 맞춘 뒤 별도 실환경 검증이 필요하다. 이 때문에 P7.6·P11.8과 전체 목표를 완료 처리하지 않는다.
