# 사진 다운로드 파일 접근 보강

2026-10-15 · 스키마 33 유지. 이미지 공급자 키 선택과 독립적인 기존 사진 CRUD 점검.

기존 코드는 소유권/공유 권한을 확인한 뒤 파일 경로에 `readFileSync`를 호출했다. 저장 파일을 심볼릭 링크로 교체하면 링크 대상의 내용까지 읽혔고, `basename`은 잘못된 저장 키를 정상 파일 이름으로 바꿔 받아들였다. 두 회귀 테스트가 실제 임시 파일에서 실패하는 것을 확인한 뒤 수정했다.

## 변경

- 서버가 생성하는 UUID+확장자 형태의 저장 키만 허용. `../` 등 다른 형태는 거절한다.
- `O_NOFOLLOW`로 최종 파일의 심볼릭 링크를 따라가지 않는다. `O_NONBLOCK`으로 특수 파일 열기에서 무기한 대기하지 않는다.
- 열린 파일 descriptor의 종류·링크 수·크기를 검사한다. 일반 파일만, 링크 수 1, 크기 1바이트~10MB를 허용한다.
- 최대 예상 크기+1만 읽고 실제 읽은 길이 및 전후 size/mtime/ctime를 검사한다.
- DB에 기록된 크기와 MIME에 맞는 파일 서명을 검사한다. 소유자 다운로드와 공개 공유 다운로드에 같은 검사를 적용한다.
- 누락·교체·손상·잘못된 키는 `404 MEDIA_UNAVAILABLE`로 반환하며 OS 경로/오류 원문을 노출하지 않는다.
- 링크로 바뀐 파일을 삭제하면 링크만 제거하고 대상 파일은 유지한다. 기존 durable 삭제 큐를 사용한다.

## 검증

신규 테스트 3개. 실제 임시 파일의 symlink·hardlink·누락·크기 변경·잘못된 서명·경로형 키·원래 파일 복구를 검사했다. API 처리기에 실제 Request를 전달해 소유자 및 공유 다운로드가 404를 반환하고 비공개 내용과 절대 경로를 응답하지 않는지 확인했다. 삭제 후 링크 대상 내용도 유지됐다. 이번 HTTP 검증은 별도 네트워크 서버/브라우저 E2E가 아닌 실제 라우트 처리기 호출이다.

전체 398개(기반 6 + 서버 392), lint/typecheck/build 통과. `evidence/media-boundary-*`에 RED/GREEN·전체 검증·소스 해시를 보존한다. 임시 파일/DB는 테스트에서 정리한다.

## 범위 제한

PNG/JPEG/WebP 서명 검사는 전체 이미지 디코딩이나 암호학적 무결성 검사가 아니다. 같은 크기·같은 형식의 내용 교체까지 탐지한다고 주장하지 않는다. 최종 파일 구성요소에 대한 no-follow 검사이며 신뢰된 업로드 디렉터리의 모든 상위 경로를 원자적으로 고정하는 openat 기반 sandbox는 아니다. 업로드 루트와 서버 파일 시스템 권한 관리는 계속 필요하다.

AI 이미지 공급자 구현/키 선택은 별도 대기 항목이며 이 변경으로 해당 요구사항을 완료 처리하지 않는다. 전체 목표와 남은 외부 연동·Ego/시각 검증 범위를 유지한다.
