# 공개 화면 시각 비교 (원본 naeo.kr ↔ 복제본)

- 실행: 2026-10-16, Chrome DevTools(실제 브라우저), 폭 1440px·390px, clone은 프로덕션 `next start`(`:3200`, `/tmp/naeo-visual` DB)
- 원본은 진행 중인 라이브 서비스다. 복제본 공개 캡처는 `2026-10-13` 스냅숏이므로, 그 사이 원본에 추가·삭제된 콘텐츠는 "원본 변동"으로 분류한다(수정 대상 아님).

## 방법

1. SSR HTML을 두 사이트에서 같은 경로로 가져와 DOMParser로 구조 지표(h1, img/section 수, header/footer, footer 링크 수)를 비교.
2. 주요 화면(`/`, `/pricing`, `/event`)을 1440·390px으로 실제 렌더링해 문서 높이·가로 넘침(`scrollWidth>innerWidth`)·렌더링 이미지 수를 측정.
3. 차이는 세 부류로 나눴다: 실제 결함 → 수정 / 원본 변동(캡처 이후 라이브가 바뀐 부분) → 추적 대상 / 의도적 대체(복제본이 캡처 그대로가 아니라 자체 데이터로 그리는 부분).

## 이번 비교에서 고친 실제 결함

1. **`/event` 대표 이미지 미표시** — `events` 테이블에 이미지 열이 없어 카드 템플릿의 포스터 영역을 통째로 지우고 있었다. 스키마 44 `cover_image`(로컬 경로만 허용) 추가, 시드 두 이벤트에 캡처된 포스터(`/assets/fc2151ea8a854a0d.png`, `/assets/2e11be7158d9feb4.png`) 연결, 목록 카드·상세 화면에 표시, 관리자 편집기에 필드 추가.
2. **`/login` 문서 제목** — 복제본이 홈 기본 제목을 그대로 썼다. 원본과 같은 `NAEO: 네이버 AI 검색(AEO) 최적화 진단`으로 맞췄다.

## 원본 변동으로 기록하는 차이(수정하지 않음)

- 홈 신규 섹션·이미지(`landing/profiles`, `landing/thennow`, `mcp/post`, `mcp/thumbs`, `mate/examples/biz.jpg` 등): 10-13 캡처 이후 원본에 추가됨.
- `/blog` 신규 글과 `blog-default-thumb.webp` 대체 썸네일.
- 홈 문서 제목(`NAEO | ` 접두어를 원본이 제거함).
- 공지 티커: 캡처 본문에는 `visibility:hidden` 상태로 들어 있고, 복제본은 이 영역 대신 자체 공지 시스템(`AnnouncementQueue`, 관리자 등록)을 쓴다. 의도적 대체.
- `/mate`의 인원·금액 수치: 원본은 SSR 플레이스홀더 후 hydration으로 채우고, 복제본은 캡처 시점 값을 표시한다. 운영 데이터라 추적하지 않는다.
