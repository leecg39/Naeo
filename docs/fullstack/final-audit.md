## 이번에 수정한 결함

- `/admin/blog` 최초 로드에서 React #418(서버/브라우저 텍스트 불일치) 재현. 서버 ICU의 `AM/PM`과 Chromium의 `오전/오후` 출력 차이가 원인이었다.
- `src/lib/kst-time.ts`의 고정 KST 포맷으로 관리자·계정·작성·공유·내보내기 화면의 날짜 표기를 통일했다. 존재하는 시각 `0`과 시각 없음 `null`도 구분한다.
- 날짜 회귀 테스트는 다른 locale 출력을 모의한 상태에서 기존 문의 포맷이 실패하는 것을 먼저 확인했고, 수정 후 통과했다. 자정·정오·연도 변경·윤일도 검증한다.
- 글쓰기 UI를 정적 검사 범위에 추가했다. 사진 공유 링크의 만료 판정 시각을 렌더링 중 계산하지 않고 조회 응답 시 상태로 저장하고, 설치되지 않은 ESLint 규칙의 무효 주석을 제거했다.

- 6개 경로의 가로 넘침을 발견해 수정했다. 설명 애니메이션 영역을 제한하고, 긴 정책 URL을 줄바꿈하며, 모바일 가이드·소셜 견본을 세로 배치한다. 내보내기 원본 1080px 캔버스는 내부 스크롤로 보존한다. 수정 전 수치는 `browser-qa/layout-before.json`에 남긴다.

- 화면 이미지 검토에서 추가로 발견한 글쓰기·공통 메뉴의 캡처 잔액(175토큰)·체험·프로필·키워드 예시를 실제 회원 데이터로 교체했다. 메뉴 7경로·다른 회원 잔액 격리·실제 공개 키워드·구독 만료를 테스트한다.

## 검증 증거

- 전체 테스트: 275개 통과(기존 스크립트 6 + 서버/도메인 269), 실패 0.
- `npm run lint`, `npm run typecheck`, `npm run build`: 종료 코드 0. lint는 글쓰기 UI와 공통 날짜 함수를 포함한다.
- 변경 후 날짜·글쓰기 HTTP 검사를 다시 실행했다. 상세 실행과 브라우저 수치는 `verification.md`의 P8.5 및 `browser-qa/summary.json`을 기준으로 한다.
- 이전 HTTP 접근 감사: 대상 83개, 정상 76·외부 연동 대기 7·실패 0. 이는 각 경로의 비로그인·관리자 접근 규칙 증거이며, 모든 기능의 외부 통합 완료를 뜻하지 않는다.
- 브라우저 점검 대상: 기존 83개 경로 + 관리자 정책·FAQ·업데이트·공지·요금제·결제와 소셜 제작 7개. 데스크톱 1440×900, 태블릿 820×1180, 모바일 390×844에서 270회 확인했다. 가로 넘침·페이지 크래시·예상 밖 오류는 0건이다.
- 동적 경로는 대표 주소로 확인한다. 유효하지 않은 공유 토큰은 오류 화면의 동작을 점검하는 사례이며, 실제 공유 사진의 정상 흐름은 기존 P4.6 기록과 이번 상호작용 검증을 구분한다.
- 실제 초안 생성·저장·새로고침 후 재열기·공유 링크 생성·철회·삭제를 UI로 확인했다. 철회한 공유 링크와 삭제한 초안은 API 404이며 테스트 데이터는 정리했다. 실제 원장과 화면 잔액도 일치했다(`browser-qa/interaction.json`).
- 없는 공유 링크 API의 의도된 404는 데스크톱·모바일에서 2건 수집됐다. 태블릿 요청 이벤트는 관찰 구간에 수집되지 않았다. 최종 배치에는 방문 집계 429가 없다.
- 스크린샷은 화면 배치 확인 증거다. 원본 사이트 전체 화면과의 정밀 시각 비교 증거로 간주하지 않는다.

원본에서 가져온 정책·FAQ·기사·브랜드·SNS 링크·연락 메일 및 요금제 혜택은 운영자가 교체·확정해야 한다. 원본에서도 누락된 대시보드 가이드 이미지 5개는 대체 콘텐츠를 만들지 않았고 404가 남아 있다. `/social/banner-preview`와 `/social/banner-preview/frame`은 홈으로 이동한다. 2026-10-15 무인증 원본 HTTP 조회에서도 두 경로의 HTML에 홈 이동 지시가 확인됐다(HTTP 200 본문에 NEXT_REDIRECT/refresh meta). 로그인·쿼리별 차이는 미확인이다. 소셜·소개 영상의 정적 견본은 실제 사용자 데이터로 간주하지 않는다.

현재 구조는 SQLite와 파일 업로드를 사용하는 단일 서버/지속 볼륨 구조다. 외부 비밀값·QA 비밀번호·DB 파일은 Git에 넣지 않는다. 실행·백업·복원·환경 분리는 `operations.md`를 따른다.
