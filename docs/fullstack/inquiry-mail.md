# 문의 답변 메일 — 스키마 31

2026-10-15. P2.4 답변 CRUD에 명시적 메일 발송 요청을 연결했다. 기존 REA는 문의 제출 계약을 확인했으며 원본 서버의 발송 처리·메일 공급자는 확인하지 않았다. 이번 암호화 큐와 Resend 연동은 자체 설계다.

## 사용·계약

관리자는 답변을 저장한 다음 **회신 이메일로 발송 요청**을 누른다. 답변 저장만으로 이메일이 발송되지 않는다. 회원과 비회원 문의 모두 문의에 기록된 회신 이메일을 사용한다. 발송 상태 새로고침으로 대기·요청 중·재시도·공급자 접수·실패를 확인한다. 공급자 접수는 받은편지함 도착을 의미하지 않는다.

POST `/api/admin/inquiries/:id/replies/:replyId/send`의 입력은 `{version}`이다. 인증·관리자·Origin·관리자 변경 빈도 제한·문의/답변 소속·낙관적 버전을 검사한다. 큐 생성·문의 버전 증가·감사 로그는 한 트랜잭션이다. 같은 답변에는 큐가 하나만 생긴다. 오래된 버전은 409이며 최신 버전으로 같은 요청을 반복하면 추가 메일 없이 현재 상태를 반환한다. 공급자 설정이 없으면 503이다.

발송 요청한 답변은 수정할 수 없다. API는 409를 반환하고 DB trigger도 본문 변경을 막는다. 정정은 새 답변으로 남긴다. 답변/문의/회원 삭제는 FK cascade로 큐를 제거하며 늦은 작업 결과가 삭제한 행을 되살리지 않는다. 이미 공급자에 전달 중이거나 전달된 메일은 삭제로 회수할 수 없다.

## 작업자와 보관

`inquiry_mail`은 답변당 UNIQUE FK, AES-256-GCM 암호화 본문, 상태, lease, 재시도 횟수/시각, 만료 시각, 안전한 오류 코드만 저장한다. 기존 계정 메일 설정과 공급자 어댑터를 재사용한다. 10,000자 답변을 지원하도록 복호화 메시지 본문 한도를 20,000자로 확장했다. 입력 답변의 기존 한도는 유지한다.

작업자는 최대 5회, 60초 lease, 15초부터 최대 5분까지 재시도 간격을 적용한다. 동일 요청 키·본문을 재사용하고 공급자 Retry-After도 반영한다. 큐는 23시간 후 만료되므로 공급자 24시간 멱등 보존 창 안에서만 재시도한다. 성공·최종 실패·만료 시 암호문을 제거한다. metadata는 답변과 함께 보관하며 원문 삭제에 종속된다.

발신자 변경/복호화 실패는 전송 없이 실패 처리한다. 실패 항목을 자동으로 새 키로 재등록하지 않는다. 요청 결과가 불확실한 실패는 운영자가 공급자 내역을 확인한 뒤 새 답변 발송 여부를 판단해야 한다. `mailState`가 새 발송 상태의 기준이며 과거 `delivery` 필드는 구형 저장 형식을 유지한다.

개인 데이터 내보내기는 소유 문의의 안전한 메일 상태를 추가해 43개 데이터셋이다. 암호화 본문과 lease·키는 내보내지 않는다.

## 실제 확인

- 신규 검증 6개(큐/공급자 5, HTTP API 1), 전체 381개(기반 6 + 서버 375) 통과. lint·typecheck·production build 통과.
- 최대 길이 답변·비회원 수신자·중복 큐·수정 차단·동일 키와 본문 재시도·삭제 중 늦은 완료·잘못된 암호화 키·만료·영구 공급자 오류 검사.
- loopback HTTP 공급자에 실제 요청을 보내 헤더/본문/접수 상태 확인. 비관리자·미인증·외부 Origin·오래된 버전 거절 확인.
- 실제 production Next와 별도 worker로 비회원 문의 접수→관리자 답변→명시적 발송→로컬 수신기 내용 일치→accepted 상태를 확인. 계정 인증/재설정 회귀도 함께 실행했다. 총 공급자 HTTP 요청 4회, 중복 제거 후 로컬 메시지 3개.
- 내보내기 실제 TAR 회귀: 43개 데이터셋과 첨부 1개, 소유권·바이트/해시·로그아웃 후 차단 검증.

근거: `evidence/inquiry-mail-runtime.json`, `inquiry-mail-export-runtime.json`, `inquiry-mail-verification.json` 및 같은 접두사 로그. 모든 임시 서버·DB·파일 정리 완료. 실제 외부 수신함 도착, Ego 관리자 버튼 클릭/hydration/시각 검증은 미완료다. 전체 목표는 active로 유지한다.
