# 전체 기능 재구현 설계

## 목표와 근거

79개 실제 URL과 4개 동적 경로를 대상으로 데이터 모델, 실제 영속 CRUD, 사용자·관리자 화면, 권한과 실행 검증을 완성한다. 기존 캡처 화면과 localStorage 데모는 출발점이며 완료 증거로 간주하지 않는다. `page-crud-matrix.md`와 `page-coverage.json`이 경로별 수용 조건이다.

REA의 공개 클라이언트에서 확인한 API는 `rea-api-evidence.json`에 보존한다. 원본 DB, RLS, 분석 알고리즘, AI 프롬프트, 결제 검증 구현은 확인되지 않았다. 아래 서버 구조·권한·스키마·계산 규칙은 새로 설계하는 구현이며 원본을 복구했다고 주장하지 않는다.

## 실행 구조

- 기존 Next.js 16 App Router + React 19 화면과 CSS/이미지 자산을 유지한다. 캡처된 개인 데이터와 데모 응답은 단계별로 실제 서버 응답으로 교체한다.
- Node.js 런타임의 Route Handler → 입력 스키마/인증/권한 → 도메인 서비스 → SQLite 관계형 DB 순서로 처리한다. SQL 파라미터 바인딩, 외래 키, CHECK/UNIQUE, 트랜잭션을 사용한다.
- DB 파일은 `NAEO_DATABASE_PATH`(기본 `var/naeo.sqlite`)에 저장하고 WAL·busy timeout을 적용한다. 로컬 및 지속 볼륨이 있는 단일 Node 서버를 지원한다. 임시 파일 시스템의 serverless 배포는 지원하지 않는다. 다중 인스턴스 운영은 PostgreSQL 이관을 별도 검증해야 한다.
- 스키마 변경은 순서가 있는 버전 마이그레이션으로만 수행한다. 테스트는 임시 DB를 사용하고 실사용 DB를 초기화하지 않는다. 백업·복원·재시작 보존을 검증한다.
- 클라이언트는 성공 응답 후에만 저장 완료를 표시한다. 처리 중/빈 상태/실패/권한 부족/충돌을 렌더링하며 동작하지 않은 외부 기능에 성공 메시지를 반환하지 않는다.

## 인증과 권한

- 이메일/비밀번호 가입·로그인을 실제 구현한다. 비밀번호는 개별 salt와 scrypt로 해시한다. 256비트 임의 세션 토큰은 HttpOnly, SameSite=Lax 쿠키에 저장하고 DB에는 SHA-256 해시만 저장한다. HTTPS에서는 Secure를 사용한다.
- 상태 변경 요청은 설정한 서비스 origin과 요청 Origin을 비교한다. API 토큰 기반 외부 연동은 별도 scope 검사 경로를 사용한다. 단순 CORS 허용으로 쿠키 인증을 노출하지 않는다.
- 모든 소유 데이터 쿼리는 인증된 user_id로 제한한다. 소유권이 없는 리소스는 404, 관리 기능은 일반 회원에게 403이다. 역할·크레딧·요금제·인증 여부는 프로필 PATCH로 변경할 수 없다.
- 관리자 초기 지정은 로컬 CLI에서 명시적으로 수행한다. 공개 회원가입의 첫 계정을 자동 관리자로 승격하거나 공유 기본 관리자 비밀번호를 만들지 않는다.
- 로그인·문의·작업 생성에는 서버 rate limit을 적용한다. 프록시 IP 헤더는 명시적으로 신뢰하도록 설정했을 때만 사용한다. 계정 탈퇴는 재인증과 트랜잭션으로 세션·개인 데이터를 삭제/익명화한다. 회계 기록 보존 정책은 구현 시 문서화한다.
- 수정에는 version을 받아 낙관적 잠금으로 덮어쓰기 유실을 막는다. 목록은 정렬·검색·페이지 크기 상한을 갖는다. 삭제 확인은 UI와 API 검증 양쪽에서 수행한다.

## 비동기 작업과 외부 서비스

- 크롤링/분석/글·이미지 생성/내보내기는 DB 작업 큐에서 queued/running/succeeded/failed/cancelled 상태와 재시도·lease를 관리한다. 재시작 시 lease 만료 작업을 복구한다. 시간 경과만으로 완료를 가장하지 않는다.
- 네이버 블로그 RSS는 허용한 HTTPS 네이버 호스트와 blog ID만 사용한다. 임의 URL, 내부 주소, 리다이렉트 우회, 큰 응답과 과도한 대기를 제한한다. 분석에는 실제 수집 내용과 측정 근거를 저장한다.
- AI 공급자는 서버 환경 변수로 설정한다. 미설정 시 503 PROVIDER_NOT_CONFIGURED로 명확히 실패한다. 오프라인 문자열 템플릿을 AI 생성 결과라고 표시하지 않는다. 유료 호출은 멱등 키와 원장 트랜잭션으로 중복 차감을 막는다.
- Google/네이버 OAuth는 등록된 앱, 정확한 redirect URI, state/PKCE/nonce 검증과 안전한 계정 연결 정책을 갖춘다. 브라우저에 로그인되어 있다는 사실은 앱 client secret이나 OAuth 동작 검증을 대신하지 않는다.
- 원본에 신규 결제 중단 플래그가 관찰되었다. 재구현 기본값도 신규 유료 판매 중단이다. 결제 공급자 설정·서버 검증·샌드박스 검증 없이 브라우저의 성공 필드만 신뢰하여 플랜을 지급하지 않는다.
- MCP는 표준 전송·도구 목록·도구 실행과 OAuth 권한 범위를 구현하고 실제 클라이언트로 확인한다. 원본 MCP 도구 스키마를 확인한 것으로 간주하지 않는다.

## 검증과 완료

도메인 테스트, DB 재연결 보존, HTTP 계약 테스트, 두 사용자/관리자 권한 격리, UI에서 생성→조회→수정→삭제, 모바일 390px·태블릿 768px·데스크톱 1440px를 확인한다. 각 경로는 행별 증거를 기록한다. 타입 검사·정적 검사·빌드 성공은 필요 조건이며 모든 기능 완료를 단독으로 증명하지 않는다. 전체 목표는 미구현·미검증 항목이 남아 있으면 active로 유지한다.
